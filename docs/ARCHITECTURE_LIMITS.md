# Tiny Isles Architecture Limits & Safety Record (설계 결정 및 한계 기록표)

> **목적:** Tiny Isles의 인프라 한계, 감당 가능한 최대 규모, 구조 교체 임계점(Trigger), 반복 패치 경보, 배포 전 필수 체크리스트를 한곳에 기록합니다.  
> **갱신 규칙:** 서버·DB·인증·실시간 통신·대규모 게임 시스템 구조가 바뀌거나 새로운 한계가 발견되면 **같은 커밋에서 반드시 이 문서를 갱신**합니다.

- **프로젝트명:** Tiny Isles
- **최종 점검일:** 2026-11-19
- **현재 운영 단계:** 프로토타입 → 4인 협동 모바일/PC 베타 준비
- **목표 규모:** 방당 최대 4인 협동, 모바일 웹 + PC 브라우저 동시 지원

## 1. 인프라 구성 및 외부 서비스 한도 (Infra & Quota Limits)

| 영역 | 사용 서비스 / 플랜 | 공식 핵심 한도 | 현재 최대 부하 추정치 | 상태 |
| :--- | :--- | :--- | :--- | :---: |
| **호스팅 / 프론트** | Vercel 정적 배포 | 정적 자산 CDN, `index.html`/`version.json` no-cache | 소규모 트래픽 여유 | 🟢 정상 |
| **인증 (Auth)** | Supabase Free (Google + Kakao OAuth) | 월 50,000 MAU | 로그인 시에만 호출 (매우 낮음) | 🟢 정상 |
| **클라우드 저장 (DB)** | Supabase Postgres Free | 500MB DB, 7일 미접속 시 자동 일시정지 주의 | 저장/불러오기 간헐적 호출 | 🟡 운영 주의 (7일 휴면) |
| **실시간 멀티플레이** | **Cloudflare Workers + Durable Objects Free** (`GameRoomDO`, `LobbyDirectoryDO`, WebSocket Hibernation) | **DO 요청 100,000/일**(WS 수신 20:1 = 200만 msg/일), **Duration 13,000 GB-s/일**, **WS 메시지 32 MiB**, 송신 대역폭 무료 | 4인 30분 매치 1판당 ~4,050 DO 요청(배치 적용 시 4.05%/일), ~225 GB-s(1.73%/일) | 🟢 **이전 완료 (Phase 1~2)** *(일 ~15판+ 시 Paid \$5/월 전환)* |

| 항목 | 현재 설계 전제 | 감당 가능 상한 | 현재 실측/추정 | 🔴 구조 교체 트리거 |
| :--- | :--- | :--- | :--- | :--- |
| **실시간 통신량 (서버)** | Cloudflare DO 단일 WebSocket + **80ms 배치 묶음 전송(`NetworkBatchQueue`)** | Free 기준 일 ~17판(안전마진 70%), Paid \$5/월 시 수백 판+ | 광역 타격·건물 피격·몬스터 공격 80ms 병합 완료 | 🟡 일일 4인 매치 15판 초과 시 **Workers Paid(\$5/월) 전환** |
| **공개 방 목록 갱신** | `LobbyDirectoryDO` WebSocket Hibernation 푸시 + 12초 최소 간격 | 변경 시에만 푸시(유휴 호출 0) | 로비 유휴 트래픽 0 | 🟢 해소됨 |
| **방 연결 흐름** | 대기실 → 인게임 **단일 WebSocket 인계(Handoff)** | 연결 끊김 0회, 서버 4인 정원·버전 강제 검증 | 단일 연결 유지 | 🟢 해소됨 |
| **사냥 모드 동시 몬스터** | **구역별 지연 스폰(1,850px) + 전역 상한(240마리) + 체력/EXP 환산 보정** | 모바일 30fps+ 안정 기준 **동시 활성 ~250~320마리** | 상한 제어 적용 완료 (기존 ~1,740마리 대비 ~80% 절감) | 🟢 **Phase 3 해소됨** |
| **상태 권한 & 동기화** | 방 서버(세션/방장) + 멱등 승급 + 충돌 환급 + `campTerritoryId`/`fieldZone` 보존 | 4인 협동 PVE (일관된 방장 권위) | 핵심 경합·방장 인계·AFK 버그 해소 (용병/자원 스냅샷은 Phase 4 레지스트리와 통합 예정) | 🟡 **Phase 4 구조 정리 예정** |

## 3. 3회 패치 중단 룰 감시 목록 (3-Patch Circuit Breaker Watchlist)

> 동일 서브시스템에서 유사·연쇄 수정이 **2회 누적되면 🟡 주의**, **3회 도달 시 🔴 패치 중단(근본 구조 재검토)** 상태로 전환합니다.

| 영역 / 서브시스템 | 최근 누적 패치 수 | 반복 증상 요약 | 상태 | 다음 조치 |
| :--- | :---: | :--- | :---: | :--- |
| **실시간 멀티 전송 / 방장 선출·이양** | 7회+ → **근본 교체 완료** | Supabase Presence 한도·3중 채널 분열·방장 눈치게임·정원 미차단 | 🟢 **구조 교체 완료** | Cloudflare `GameRoomDO` 단일 연결 + 80ms 배치 큐 + 프레임 보간 적용 완료 |
| **신규 콘텐츠 멀티 동기화 배관** | **3회+** | 35종 중앙 수동 배관 비대화 및 용병·자원 스냅샷 동기화 | 🟡 **Phase 4 예정** | 타입 안전 도메인 이벤트 버스 + 스냅샷 레지스트리로 구조 단순화 |

## 4. Tiny Isles 신규 기능 완료 시 교차 체크리스트 (Feature Cross-Check)

신규 직업·스킬·건물·몬스터·모드·오브젝트를 추가할 때, 싱글 플레이 동작만으로 완료 처리하지 않고 아래를 반드시 점검합니다.

- [ ] **실제 연결 경로(E2E Wiring):** React 로비/HUD → 훅 → Transport → Phaser 씬/시스템까지 값이 빠짐없이 전달되는가? (특히 `?:` 선택 필드의 모든 호출부 확인)
- [ ] **원격 플레이어 동기화:** 다른 팀원 화면에도 오브젝트·스킬·소환수(용병)·체력 변화가 동일하게 보이는가?
- [ ] **중도 합류(Drop-in) 스냅샷:** 게임 도중 합류한 유저에게도 현재 상태가 빠짐없이 전달되는가?
- [ ] **방장 이양(Failover) 인계:** 방장이 백그라운드 전환/이탈해 새 방장으로 바뀌어도 소속 정보·진행 중 타이머/스폰이 끊기지 않는가?
- [ ] **정원·경합·중복 방지:** 4인 정원 초과, 동시 승급/건설/수리 시 중복 적용이나 자원 증발이 없는가?
- [ ] **모바일 4인 부하:** 4인 배율 적용 시 동시 활성 엔티티 수와 초당 메시지 수가 상한(한도의 70%) 이내인가?

## 5. 배포 전 최종 게이트 (Pre-Deploy Gate)

Vercel 프로덕션 배포 전 반드시 아래 항목을 확인합니다.

- [ ] **빌드 및 테스트 통과:** `npm run build` 및 `npm test` 통과
- [ ] **`dev` vs `prod` 분기 전수 점검:** `isDevBuild()` 등 개발 모드에서만 꺼지는 가드가 프로덕션 빌드에서 정상 동작하는지 확인 (예: 대기실 `appVersion` 전송 누락 여부)
- [ ] **초대 링크 & 중도 합류 실흐름 확인:** `?room=XXXXXX` 최초 접속 시 방 목록 수신 완료 후 대기실/진행 중 방으로 정확히 분기되는지 확인
- [ ] **실시간 통신량 & Presence 주기 점검:** Presence 갱신 주기가 서버 제한(30초당 5회)을 넘지 않고, 4인 교전 피크 통신량이 한도 70% 이내인지 확인
- [ ] **캐시·버전 매니페스트 점검:** `vercel.json` 헤더 및 `/version.json` 생성 여부 확인
